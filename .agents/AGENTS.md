# AGENTS.md

Guidance for work in this home directory: CachyOS with Niri + DankMaterialShell (DMS), managed with chezmoi and shared by a desktop PC and a laptop.

This is the single shared copy: `~/AGENTS.md` is a symlink to `.agents/AGENTS.md` inside the chezmoi source (`~/.local/share/chezmoi`). Edit it here — changes land directly in the repo; commit them with git in the source directory. Always update it after any system, config, service, package or environment change.

## General practice

- Inspect the current state before changing it; preserve unrelated user changes.
- Prefer application settings and supported commands over hand-editing managed/generated files.
- Make the smallest useful change, then validate the affected service or configuration.
- Treat optional or hardware-dependent features as opt-in; do not install them without a clear use.
- Never store passwords or weaken authentication policy to make automation easier.

## Machines and dotfiles

- Dotfiles/system config are managed by chezmoi from `quantavil/dotfiles`. Replicate a new machine with: install CachyOS + Niri, `chezmoi init --apply quantavil`, then `sudo pacman -S --needed - < ~/.local/share/chezmoi/pkglist-pacman.txt`. `pkglist-pacman.txt`/`pkglist-aur.txt` are refreshed by pre-commit git hooks in the repo.
- Detect the machine from hardware, never hostname: `cat /sys/class/dmi/id/chassis_type` (3 = desktop, 9/10 = laptop), `ls /sys/class/power_supply/` (no `BAT*` = desktop), `lspci | grep -qi nvidia` (desktop). Each machine keeps an untracked `~/.config/chezmoi/chezmoi.toml` with `[data] role = "desktop"`/`"laptop"`; templates check `{{ eq .role "desktop" }}`.
- Desktop: i5-12400F (no iGPU) + RTX 4060 (nvidia-open), single LG ULTRAGEAR 1920x1080@144 on HDMI-A-2; DMS `networkPreference=wired`, no battery widget. OBS Studio + browser plugin (NVENC via RTX 4060; PipeWire capture through `xdg-desktop-portal-gnome`); virtual camera via `v4l2loopback` DKMS module (autoloads via `/etc/modules-load.d/v4l2loopback.conf`). AVD `ditto2_play_x86_64` (Play x86_64 + ARM64 translation, signed into Google Play — keep it): run with `-port 5556 -gpu host`; `DITTO_GPU=host` is verified.
- Laptop: Intel UHD (no Nvidia), battery. Keep `DITTO_GPU` unset/auto here (headless host-GPU on the Intel iGPU is unreliable). AVDs `floww_fresh`, `floww_light`, `floww_parity` (Android 34 `google_apis` x86_64, no Play Store).
- Accepted machine differences: the laptop keeps AyuGram `x-scheme-handler/tg` ids (`6JXKV3`/`QT4KV3`), its own `mise/config.toml` (adds `flutter`/`node`/`pnpm`), a standalone Codex CLI, and `chatgpt-desktop-bin` (which owns `x-scheme-handler/codex`); `text/html` opens in Vivaldi on the desktop and Zen on the laptop.
- Intentional chezmoi drift — app-generated runtime state; do not commit or "fix" without asking: `.config/kdeglobals`, `.config/shelly/settings.json`, `.config/DankMaterialShell/*.json`.

## Desktop session (Niri + DMS)

- Niri config: `~/.config/niri/config.kdl`. Everything under `~/.config/niri/dms/` is generated by DMS — change DMS settings or add includes/overrides to the main config instead. User binds placed after the DMS includes override defaults; keep obsolete shell/lock commands out, and lock via the DMS lock interface.
- Custom binds: `Mod+B` default browser, `Mod+E` Dolphin, `Mod+Z` VS Code, `Shift+Print` regional OCR (`~/.local/bin/dms-ocr`), `Mod+Alt+C` DMS color picker, `Mod+Shift+E` power menu (replaces the session-exit default).
- DMS runs as `dms.service`; use DMS IPC for shell features and settings. Keyboard auto-detection needs `libinput-tools`.
- Window rules: opaque by default; one `window-rule` adds `opacity 0.88` + blur for Rio, Dolphin, Nautilus, Ark, Filelight, pavucontrol, Fooyin and `com.danklinux.dms` — add further translucent apps there. Global `blur { passes 1 offset 1.0 }`; OBS windows stay fully opaque.
- Terminal: Rio (`~/.config/rio/config.toml`, MesloLGS Nerd Font Mono, `opacity = 1.0` + `unfocused-split-opacity = 1.0` so Niri alone controls translucency). CLI editor: Zed via `~/.local/bin/zedit` (`zeditor --wait`), exported as `EDITOR`/`VISUAL`.

## Theme, fonts, environment

- Qt platform theme: `xdgdesktopportal` (`~/.config/environment.d/90-dms.conf` + Niri environment block), because `qt6ct-kde` 0.11 is built for Qt 6.11 and its plugin fails on Qt 6.12 — revisit only after it is rebuilt. DMS still writes `~/.config/qt6ct/qt6ct.conf` on theme changes; do not overwrite generated theme files — apply via DMS, then reopen affected apps.
- Icons: `BeautyLine`; fonts: `MesloLGS Nerd Font` — set for both Qt (`~/.config/qt6ct/qt6ct.conf`) and GTK/GNOME (`gsettings org.gnome.desktop.interface`).
- Session variables belong in `~/.config/environment.d/90-dms.conf` and Niri's `environment` block; a new login session is required after changing them. System locale: `en_IN.UTF-8` (`/etc/locale.conf`).
- `vim` stays installed (`cachyos-zsh-config` requires it) but `vim.desktop` is masked in `~/.local/share/applications/`.

## Files, terminals, app defaults

- Terminal: Rio via `~/.config/kdeglobals [General]` (`TerminalApplication=rio`, `TerminalService=rio.desktop`) + `~/.config/xdg-terminals.list`.
- Editor: Zed for ~35 code/text types (incl. `text/csv`, by choice). Not Zed: html/URLs → browsers; xls/xlsx/xlsm → Gridcraft; doc/docx → Wordcraft; psd → Photocraft; ppt/pptx/potx/ppsx/odp → Deckcraft; pdf → PdfCraft (declares only `application/pdf`; `application/x-pdf` is unset); `.ipynb`/`.code-workspace`/markdown → VS Code (`com.microsoft.VSCode.desktop` — VS Code ships no `code.desktop`); binaries → no default.
- Inspect with `gio info <file> | grep content-type` and `xdg-mime query default <type>`; set defaults with `xdg-mime default`. Editor switch: replace `dev.zed.Zed.desktop` in `mimeapps.list` and retarget the `zedit` shim. Terminal switch: `kwriteconfig6 --file kdeglobals --group General --key TerminalApplication <cmd>` + `--key TerminalService <id>.desktop`, then update `xdg-terminals.list`.

## Services and integrations

- Manage user components with systemd user services; inspect first (`systemctl --user status`, `journalctl --user -u <unit>`; `journalctl -k` for device/filesystem/firewall issues).
- DankSearch backs DMS filesystem search (`dsearch index status`, `dsearch.service`).
- Firewall: UFW, default-drop incoming; only narrow rules for features in use. Open: KDE Connect (`1714:1764` tcp+udp, `kdeconnectd` — diagnose discovery before touching the firewall); MicYou `8554/tcp` (control), `8555/udp` (audio), `8443/tcp` (web). Clients must target the host's current DHCP address — never hardcode host IPs in device profiles.
- MCP servers: centralized in `~/Documents/my-mcps`, deployed by `bun run deploy` to Antigravity, OpenCode, Codex, Cursor, Claude Desktop and Claude Code. Entries include `awwwards` (design search; browser-capture tools need optional Playwright/ffmpeg; the local index builds on a 7-day gate; manual build `npx -y -p awwwards-mcp awwwards-index`), `ditto2`, `ditto-jadx`/`ditto-apktool`/`ditto-r2flutter`/`ditto-mobile-control`, and `github` (needs a token). `mobile-mcp` was removed at the user's request — do not re-add it. Restart/reconnect clients after config changes.
- Skills: managed in `~/Documents/my-skills` (`bun index.ts` or `./run.sh <command>`: add/remove/sync/set/superskill/enable/disable/status/deploy/doctor/check). `skills.json` is committed; `superskills/` is generated; `.active/` + `skills.local.json` are per machine. Deploy installs symlinks for all agent targets; Gemini/OpenCode read `.active/`, so disabled skills stay hidden. Upstream skills come from the pinned `skills` devDependency — never a floating `bunx`. List current skills with `bun index.ts status`.
- SMB (desktop): `DESKTOP-CNRKSBM` is at `desktop-cnrksbm.local` (192.168.1.5), Dolphin uses `smb://` (shares `E`, `Users`); `kio-fuse.service` maps KIO URLs into `/run/user/1000/kio-fuse-*/` for non-KDE apps.
- Printing/scanning (desktop): HP LaserJet Pro MFP M125nw on USB + HP LaserJet 1020 on `DESKTOP-CNRKSBM`; both need the proprietary `hplip-plugin`; stack = `cups`/`cups-filters`/`hplip`, `sane`/`sane-airscan`, `skanpage`/`simple-scan`.

## Privileged operations

- Packages: `pacman` (official/CachyOS) first, `shelly` for AUR. Prefer prebuilt binaries; ask explicit permission for even small source builds. Group related changes into one transaction; verify exact devices/packages/paths/commands before requesting authentication.
- Use `pkexec` with an absolute executable path — no general root shell. Do not weaken sudoers/Polkit, enable NOPASSWD, store passwords, or create persistent elevated helpers.
- Headless agents: `pkexec` via the DMS polkit agent works for short, already-verified root work, but its authorization expires quickly. For long `pacman` runs use a mode-700 `SUDO_ASKPASS` helper under `/tmp/opencode` and `shred -u` it afterwards. `shelly` elevates through `sudo` and fails without a TTY — for scripted runs use `pacman` directly (a PATH shim that only prepends `-A` to sudo works for shelly if needed).
- `checkupdates` syncs its own database copy and can report stale results; confirm with `pacman -Syu`.

## Storage and recovery

- Before repairs: identify the filesystem and read kernel logs; prefer a read-only mount when consistency is uncertain; confirm the exact unmounted device before running repair tools; never format as a repair step. Check drive health on I/O errors. `ntfsfix` is limited recovery — recommend a Windows `chkdsk` follow-up. Mount removable storage through UDisks and eject cleanly.

## Validation

- `niri validate -c ~/.config/niri/config.kdl`; `dms doctor -j` plus DMS IPC status; `journalctl --user -u <service>`; `journalctl -k`. After changes, confirm both configuration validity and the actual runtime state.
